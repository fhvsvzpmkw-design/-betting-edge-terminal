## Startup and bounded capability test

1. Read the current shared authority, resolve the exact lane and follow its normal odds intake. Start/resume and remotely verify the initial checkpoint before broad research. Do not replace an already-running producer or edit a frozen candidate for this rollout.
2. Inspect the delegation tools actually exposed to this execution. Use their documented API; names can differ by runtime. If spawning is absent, record AGENTS_UNAVAILABLE with the actual missing capability and continue the existing coordinator event loop immediately. A prompt, an Ultra setting or another chat's tools is not launch evidence.
3. When spawning is exposed, launch six distinct child threads before assigning research: researcher-1 through researcher-4 and reviewer-1 through reviewer-2. Each receives its role, actual run/candidate/checkpoint/feed binding and read-only boundary, and returns a short acknowledgment echoing that binding. The acknowledgment must perform no source retrieval, odds request, handicap or shared mutation. Reuse these same six threads for the real work; do not launch six additional workers. Keep no more than six child threads open at once.
4. Bound this startup check to 60 seconds total, measured from the first launch. Record actual thread IDs, coordinator-observed launch/acknowledgment clocks, mismatches and tool errors. Do not invent worker times or infer simultaneous computation from six IDs. Six successful launches and correctly bound acknowledgments establish capacity for six open worker threads in this task/run. Record any actual overlap observable from tool activity separately; mark unavailable execution telemetry unknown.
5. If all six acknowledge, record AGENTS_READY and start the approved team below. On a missing tool, capacity rejection, binding mismatch or timeout, stop/release the launched workers using the available runtime controls, record AGENTS_FALLBACK and the exact reason, and continue the normal coordinator loop. Prevent late worker writes by granting none. Do not repeatedly probe within this run, silently substitute a smaller agent team, fabricate parallel activity or let this test veto publication. An agent failure never authorizes disabling or rescheduling a report task.

Use the existing task execution result as the primary activity record. The coordinator may persist a compact informational receipt at data/report-production/agent-receipts/<run-id>.json alongside the existing production artifacts. Include schema=1, taskId, executionRunId when exposed (otherwise null), checkpointPath, candidateId, feedBlobSha, actual mode/reason, worker role/ID/launch/acknowledgment/error entries and actual completed event/review counts. Do not write secrets, full tool inventories, repeated source payloads or guessed account usage. The receipt is not betting evidence, a new queue or a publication gate. A receipt-save failure is disclosed separately and must not stop saving research or publishing the report.

## Review and merge

Reviewer-1 and reviewer-2 receive disjoint queues of proposed actionable selections and material disagreements as results arrive. Each checks original evidence, identity, settlement, pricing, attribution, personnel/model assumptions and the strongest opposing case. Their agreement is a check, never an independent source. Return specific corrections, unresolved questions and decision impact with original bindings. With no reviewable item, remain idle; there is no quota to create picks or criticism.

Only the coordinator reconciles findings and changes the draft. Check exact identity, source provenance, original clocks and present applicability. A worker's older assignment revision is not authority to overwrite a newer draft: fetch/export the latest checkpoint, reconcile only that event's evidence and exact selections, and save with the current expected revision and `checkpoint --event-id`. Preserve already merged events and remote changes. A conflicting revision requires reload/reconciliation. Reassign an event only after stopping/releasing its former owner and recording which results remain usable. Never merge a worker's whole stale draft over the coordinator draft.

Save completed events incrementally without waiting for every researcher or reviewer. Bound follow-up to consequential missing facts under the existing initial/deeper/final research process. A worker crash or delay leaves its exact unanswered work visible; stop that assignment and complete eligible work in the coordinator loop. Reviewer completion is not a new report-wide gate. Independently completed validated cards can publish under the existing partial-publication rules. Preserve all decision-specific research and betting requirements.
